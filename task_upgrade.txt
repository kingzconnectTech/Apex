# Apex Prediction Engine Upgrade — Goals, Corners and Bookings

## OBJECTIVE

Upgrade the existing Apex sports prediction application to calculate football match goals, corners, and total bookings using a statistically sound, data-driven prediction engine.

Implement these markets:

1. **Over/Under Total Match Corners**
2. **Over/Under Total Match Bookings**

The system must analyse each team's last 10 relevant matches, historical H2H results, home/away performance, competition statistics, and available match-specific data.

Do not simply use averages or randomly generated probabilities. Build a reliable statistical pipeline that calculates expected values, estimates probability distributions, evaluates uncertainty, and validates its predictions against historical results.

## PHASE 1 — AUDIT THE EXISTING CODEBASE

Before modifying anything:

- Inspect the complete existing Apex repository.
- Identify the current prediction engine, `PredictionEngine`, `EnsembleManager`, data providers, database models, fixture services, prediction APIs, and frontend prediction components.
- Identify how ESPN and the existing secondary football API are integrated.
- Check whether the existing ARIMA, Prophet, LSTM, or other models are actually being used and evaluated correctly.
- Identify which provider supplies goals, corners, yellow cards, red cards, and match statistics.
- Check data freshness, missing statistics, duplicate fixtures, team-name matching, competition identifiers, and historical data coverage.
- Preserve working functionality and existing integrations.
- Reuse existing services and models where appropriate. Do not create a duplicate prediction engine or replace working infrastructure without a clear technical reason.
- Produce a brief implementation plan, then implement the upgrade.

## PHASE 2 — BUILD A RELIABLE HISTORICAL DATASET

For every upcoming fixture, retrieve the most recent 10 completed matches for both teams, where available.

For each historical match, collect:

- Match date and competition.
- Home team and away team.
- Full-time home and away goals.
- Half-time score, if available.
- Home and away corners, if available.
- Home and away yellow cards, if available.
- Home and away red cards, if available.
- Total corners.
- Total yellow cards.
- Total red cards.
- Match venue and home/away designation.
- Expected goals (xG), shots, shots on target, and possession, where available.
- Match status and source identifiers.

Use only completed, valid matches for historical calculations. Exclude abandoned matches and avoid treating missing statistics as zero.

### Last-10 analysis

For each team, calculate:

- Average goals scored and conceded.
- Median goals scored and conceded.
- Percentage of matches scoring 0, 1, 2, 3 or more goals.
- Percentage of matches conceding 0, 1, 2 or 3+ goals.
- Average corners won and conceded.
- Median corners won and conceded.
- Average yellow cards and red cards.
- Average total bookings per match.
- Frequency of each proposed over/under threshold.
- Home-only performance for the home team.
- Away-only performance for the away team.
- Recent form and changes in performance over the last 5 versus the last 10 matches.

Use the full last-10 sample as the main window, while using the last 5 as a recency indicator. Do not allow a small recent sample to dominate the calculation.

When fewer than 10 valid matches exist, use the available sample but lower the data-quality score. Do not invent missing matches or statistics.

## PHASE 3 — H2H ANALYSIS

Retrieve relevant historical head-to-head matches between the two teams.

Calculate:

- Average home and away goals in H2H.
- Home-team and away-team goal distributions.
- Average total corners.
- Average corners for each team.
- Average yellow cards, red cards, and total bookings.
- Frequency of the proposed over/under outcomes.
- Sample size, dates, and age of the H2H matches.

Give more weight to recent, relevant H2H matches, but reduce their influence when the sample is small or the teams' circumstances have changed substantially.

Use a configurable H2H lookback window and a sensible maximum sample size. Prefer matches from comparable competitions and account for home/away context.

**Important:** H2H must not override stronger current team data. Old H2H results should receive less weight, and a small H2H sample must not create false confidence.

## PHASE 4 — CALCULATE EXPECTED GOALS

Implement a statistically appropriate goals model.

### A. Estimate each team's expected goals

Calculate:

- `home_expected_goals`
- `away_expected_goals`

Combine relevant information from:

- Home team's recent scoring record.
- Home team's recent goals conceded.
- Away team's recent scoring record.
- Away team's recent goals conceded.
- Home-only and away-only splits.
- Relevant H2H data.
- Competition-specific scoring averages.
- xG data, when reliable and available.
- Recency and sample-size adjustments.

Use a documented weighted or hierarchical approach. Shrink noisy team estimates towards the relevant competition average instead of trusting unstable small samples.

Avoid double-counting the same information when combining features.

### B. Estimate probabilities for team goals

Use a suitable probability distribution, such as Poisson, with an appropriate adjustment if validation shows that a basic Poisson model is insufficient.

Calculate:

- Probability the home team scores 0, 1, 2, 3+ goals.
- Probability the away team scores 0, 1, 2, 3+ goals.

For an initial Poisson model:

`P(X = k) = exp(-λ) × λ^k / k!`

Where `λ` is the team's expected goals.

Ensure the final probabilities are valid, properly normalized, and consistent with the model's assumptions.

## PHASE 4 — CALCULATE EXPECTED CORNERS

Build a separate corners prediction model. Do not reuse the goals model for corners.

Estimate:

- Expected home-team corners.
- Expected away-team corners.
- Expected total match corners.

Use:

- Home team's last-10 corners won and conceded.
- Away team's last-10 corners won and conceded.
- Home/away splits.
- H2H corner statistics.
- Competition corner averages.
- Shots, shots blocked, attacks, possession, and other relevant features where available.
- Recency, data quality, and sample size.

Combine the attacking corner rate of one team with the opponent's corner-concession rate. Adjust for competition context and shrink unreliable estimates towards the competition average.

### Corner probability distribution

Use a count-data model appropriate to the observed distribution, such as Poisson or negative binomial. Evaluate overdispersion and choose the model based on out-of-sample validation.

Calculate the probability of total corners being above or below each configured market line.

Support configurable lines such as:

- Over/Under 7.5 corners.
- Over/Under 8.5 corners.
- Over/Under 9.5 corners.
- Over/Under 10.5 corners.
- Over/Under 11.5 corners.

Do not hardcode the list in a way that prevents future configuration.

For each line, calculate both probabilities from the same underlying distribution. Ensure they are complementary for a two-outcome, half-goal line.

Use the total-corners distribution or a validated joint model for the sum of home and away corners. Do not simply add average corners and present that sum as a probability.

If the model predicts 9.2 expected corners, that does not mean Over 8.5 has a 92% probability. Probability must come from the estimated distribution and its validation.

## PHASE 6 — CALCULATE TOTAL BOOKINGS

Treat bookings as a separate statistical target.

First inspect the data provider's definition of cards and the existing database schema.

Record separately:

- Home yellow cards.
- Away yellow cards.
- Home red cards.
- Away red cards.
- Total yellow cards.
- Total red cards.
- Total bookings under the provider's documented convention.

Do not silently mix yellow cards, red cards, and booking points. Some providers count a second yellow leading to a red differently, so use one documented convention consistently across historical data, predictions, settlement, and display.

Estimate expected bookings using:

- Both teams' last-10 card records.
- Home/away splits.
- H2H card history.
- Competition-specific card averages.
- Referee card averages, only if reliable referee data is available.
- Team foul rates and relevant defensive statistics, if available.
- Match importance or rivalry indicators only when grounded in reliable data.
- Sample size and recency.

Use a Poisson or negative-binomial count model based on empirical validation. If yellow cards and red cards have meaningfully different effects, model them separately and combine them according to the chosen market settlement convention.

Support configurable half-goal lines, such as:

- Over/Under 2.5 total bookings.
- Over/Under 3.5 total bookings.
- Over/Under 4.5 total bookings.
- Over/Under 5.5 total bookings.
- Over/Under 6.5 total bookings.

Generate over/under probabilities from the estimated distribution, not from simple averages alone.

If reliable card statistics are missing, mark the bookings market as unavailable. Never substitute zero cards for missing data.

## PHASE 7 — MODEL ENSEMBLE AND PROBABILITY CALIBRATION

Inspect the current `PredictionEngine` and `EnsembleManager` before deciding how to integrate the new models.

Use separate target-specific models for:

- Home-team goals.
- Away-team goals.
- Total corners.
- Total bookings.

An ensemble may combine suitable models, but it must not average model outputs blindly.

Requirements:

1. Compare candidate models using chronological train/validation/test splits.
2. Train only on information available before the target match.
3. Prevent data leakage from future results, current match statistics, or post-match information.
4. Use rolling-origin backtesting where practical.
5. Calibrate predicted probabilities using methods such as isotonic regression or Platt scaling when supported by sufficient validation data.
6. Use Brier score, log loss, calibration curves, and appropriate count-prediction errors to evaluate the models.
7. Compare against simple baselines, including competition averages and basic Poisson estimates.
8. Prefer the simplest model that performs reliably out of sample.
9. Do not claim an accuracy improvement unless backtesting supports it.
10. Retrain and recalibrate using a controlled process, with model versions recorded.

The model must be able to abstain when its data or validation is insufficient.

## PHASE 8 — PREDICTABILITY AND RECOMMENDATION FILTER

A high estimated probability does not automatically make a match safe.

Create a separate predictability assessment using:

- Historical data completeness.
- Sample size.
- Reliability of the competition and provider statistics.
- Stability of recent performance.
- Model agreement.
- Probability calibration quality.
- Backtested performance for the specific market.
- Missing data and uncertainty.

Keep these concepts separate:

- **Estimated probability:** the model's estimated chance of the outcome.
- **Data quality:** the completeness and reliability of the inputs.
- **Model confidence:** how stable the estimate is under reasonable changes in inputs and assumptions.
- **Historical performance:** how the market model performed on held-out historical matches.

Only recommend a market when it passes configurable minimum data-quality and validation requirements.

A provisional 75% probability threshold may be used for testing, but it must not be described as a verified 75% win rate. Validate and calibrate the threshold before presenting it as a reliable selection rule.

Do not force a prediction for every fixture. Display a clear “Insufficient data” or “No recommended market” state when appropriate.

Keep all fixtures available in the application, but separate:
- All available matches.
- Matches with sufficient statistical data.
- Recommended predictions.
- Rejected or unavailable markets, with reasons.
